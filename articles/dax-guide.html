DAX别裁新解：诠释新视角

📅 2025年11月15日 ⏱️ 阅读时间：20分钟

一、入门：分析概念

1. 分析本质和度量值

  • 分析的本质是抽象
  • 抽象的实现形式为聚合（由明细到问题）
  • 聚合的结果为度量（业务称为指标）

比如SQL的GROUP BY、Excel的透视、DAX的Context

2. 数据准备与辅助列（计算列）

分析之前的准备（问题缺少的要素），计算列一般非聚合（可以是行级别的预先聚合），通常是行级别，是预先的计算。

3. 百变筛选及筛选器

筛选是判断T/F，返回一个中间表，和计算的阶段无关。

4. 问题构成和计算上下文（Context）

影响聚合的要素称为上下文/环境/Context，用表的逻辑理解，嵌套性原则。

5. 典型数据查询

  • Project - 列查询
  • Filter - row by row筛选
  • Summarize - 分组聚合

二、进阶篇：Expression

1. Excel和DAX的日期函数

行级别函数/表达式，数据准备性质，如YEAR/DATEDIFF

2. 明细级别SUM+IF/SUMIF到SUMX

新建列：SUM+IF是行级别计算，SUMIF = SUMX + FILTER

3. 问题阶段SUM+IF/SUMIF到SUMX

透视表：IF+SUM，IF优先筛选器，SUM+IF不可行，用SUMX效率更高。

4. 为度量增加前置筛选：从SUMX到CALCULATE

CALCULATE vs SUMX
  • CALCULATE改变筛选上下文，可嵌套
  • SUMX向下兼容，适用于行级别/问题级别
  • CALCULATE向上兼容，仅适用于问题级别

5. SUMMARIZE表达式

  • SUMMARIZE：table, groupbycolumn, name, expression
  • SUMMARIZECOLUMNS：groupbycolumn, filtertable, name, expression

三、高级篇：表操作

1. 一切皆是表操作

表可以视为关系的实例，SQL/DAX都是表操作语言。

2. 表操作的三种类型

  • 筛选（WHERE） - 表的行子集
  • 投影（SELECT column） - 表的列子集
  • 扩展（JOIN/UNION） - 创建新行/列

3. 上下文转换

  • 使用CALCULATE将行上下文转换为筛选上下文
  • 使用SUMMARIZECOLUMN增加measure

4. 重新理解上下文转换

  • SUMMARIZE是增加度量值，自带筛选上下文——从明细表到问题的汇总
  • ADDCOLUMNS是增加计算列，需要使用CALCULATE转换筛选上下文——从明细表到明细表的扩展

四、高级案例分析

1. Customer Order Frequency 客户频次分析

二次聚合问题：

  • Tableau使用FIXED预先聚合
  • SQL使用子查询/中间表
  • DAX方法一：使用SUMMARIZECOLUMNS创建中间表
  • DAX方法二：使用计算列预先聚合

2. Cohort Analysis 阵列分析

用户分群与留存分析的经典场景

3. Daily Profit KPI 每日利润判断

结合时间维度的动态指标计算

4. Percent of Total 合计与优先级

理解ALL、ALLEXCEPT、ALLSELECTED的区别与应用场景

五、总结

DAX的核心在于理解上下文的概念，掌握表操作的思维方式。从SUMX到CALCULATE，从行上下文到筛选上下文，每一步都需要深入理解其背后的逻辑。
