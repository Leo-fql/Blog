影响SQL性能的写法

📅 2025年10月10日 ⏱️ 阅读时间：10分钟

一、避免在WHERE子句中使用IS NULL或IS NOT NULL

❌ 不推荐： 
SELECT id FROM table WHERE name IS NULL

这会导致全表扫描，无法使用索引。

二、避免在WHERE子句中使用!=或<>操作符

数据库在查询时，对 != 或 <> 操作符不会使用索引，而对于 <、<=、=、>、>=、BETWEEN AND，数据库才会使用索引。

❌ 不推荐： 
SELECT name FROM table WHERE id <> 0
✅ 推荐： 
SELECT name FROM table WHERE id < 0
UNION ALL
SELECT name FROM table WHERE id > 0

三、避免在Where子句中使用OR链接条件

❌ 不推荐： 
SELECT id FROM table WHERE name = 'Value1' OR name = 'Value2'
✅ 推荐： 
SELECT id FROM table WHERE name = 'Value1'
UNION ALL
SELECT id FROM table WHERE name = 'Value2'

四、少用IN或NOT IN

虽然对于IN的条件会使用索引，不会全表扫描，但在某些特定情况，使用其他方法也许效果更好。

❌ 不推荐： 
SELECT name FROM table WHERE id IN(1,2,3,4,5)
✅ 推荐（连续数值）： 
SELECT name FROM table WHERE id BETWEEN 1 AND 5

五、注意LIKE中通配符的使用

❌ 不推荐（全表扫描）： 
SELECT id FROM table WHERE name LIKE '%Value%'
SELECT id FROM table WHERE name LIKE '%Value'
✅ 推荐（使用索引）： 
SELECT id FROM table WHERE name LIKE 'Value%'

六、避免在Where子句中对字段进行表达式操作

❌ 不推荐： 
SELECT name FROM table WHERE id/2 = 100
✅ 推荐： 
SELECT name FROM table WHERE id = 100*2

七、避免在Where子句中对字段进行函数操作

❌ 不推荐： 
SELECT id FROM table WHERE SUBSTRING(name,1,8) = 'Value'
SELECT id FROM table WHERE DATEDIFF(day,datefield,'2024-07-17') >= 0
✅ 推荐： 
SELECT id FROM table WHERE name LIKE 'Value%'
SELECT id FROM table WHERE datefield <= '2024-07-17'

八、在子查询中用EXISTS代替IN

❌ 不推荐： 
SELECT name FROM a WHERE id IN(SELECT id FROM b)
✅ 推荐： 
SELECT name FROM a WHERE EXISTS(SELECT 1 FROM b WHERE id = a.id)

九、SQL什么时候不走索引

  1. 条件字段选择性弱，查出的结果集较大，不走索引
  2. Where条件等号两边字段类型不同，不走索引
  3. 优化器分析的统计信息陈旧也可能导致不走索引
  4. 索引字段 IS NULL 不走索引
  5. 对于COUNT(*)当索引字段有NOT NULL约束时走索引，否则不走索引
  6. LIKE后面的字符当首位为通配符时不走索引
  7. 使用不等于操作符如：<>、!= 等不走索引
  8. 索引字段前加了函数或参加了运算不走索引

十、总结

核心原则：不要在Where子句中的"="左边进行函数、算术运算或其他表达式运算。

遵循这些最佳实践，可以显著提升SQL查询性能，减少数据库负载。
